## Часть I. Повторение (0–10 минут)

Вопросы студентам:

- Что делают `INSERT`, `UPDATE`, `DELETE`?
- Чем функция отличается от процедуры?
- Когда срабатывает триггер?
- Что произойдёт, если первая SQL-команда выполнится, а следующая завершится ошибкой?

**Проблемная ситуация:** при переводе денег нужно списать сумму у отправителя и зачислить её получателю. Если сохранить только списание, деньги исчезнут. Транзакция помогает выполнить обе операции как единое целое.

## Часть II. Понятие транзакции (10–25 минут)

**Транзакция** — последовательность одной или нескольких операций с базой данных, рассматриваемая как единое целое. При ошибке изменения транзакции можно отменить, а при успехе — подтвердить.

Пример: у Али 10 000 ₽, у Мурада 3 000 ₽. После перевода 5 000 ₽ должно стать 5 000 ₽ и 8 000 ₽ соответственно. Общая сумма остаётся 13 000 ₽.

### Подготовка таблицы

```sql
CREATE TABLE accounts (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    owner VARCHAR(100) NOT NULL,
    balance NUMERIC(12, 2) NOT NULL CHECK (balance >= 0)
);

INSERT INTO accounts (owner, balance)
VALUES
    ('Али', 10000),
    ('Мурад', 3000),
    ('Анна', 15000),
    ('Давид', 7000);

SELECT * FROM accounts ORDER BY id;
```

`CHECK (balance >= 0)` запрещает отрицательный баланс. Это пригодится при демонстрации ошибки.

## Часть III. BEGIN, COMMIT, ROLLBACK (25–40 минут)

| Команда | Назначение |
|---|---|
| `BEGIN` | Начать транзакцию |
| `COMMIT` | Подтвердить изменения |
| `ROLLBACK` | Отменить изменения текущей транзакции |

### Пример 1. Успешный перевод

```sql
BEGIN;

UPDATE accounts
SET balance = balance - 1000
WHERE id = 1;

UPDATE accounts
SET balance = balance + 1000
WHERE id = 2;

COMMIT;

SELECT * FROM accounts ORDER BY id;
```

Результат: у Али 9 000 ₽, у Мурада 4 000 ₽. После `COMMIT` обычный `ROLLBACK` уже не отменит подтверждённые изменения.

### Пример 2. Отмена перевода

```sql
BEGIN;

UPDATE accounts
SET balance = balance - 2000
WHERE id = 1;

UPDATE accounts
SET balance = balance + 2000
WHERE id = 2;

ROLLBACK;
```

После `ROLLBACK` балансы вернутся к состоянию до начала этой транзакции.

### Пример 3. Ошибка внутри транзакции

```sql
BEGIN;

UPDATE accounts
SET balance = balance - 1000
WHERE id = 1;

UPDATE accounts
SET balance = -500
WHERE id = 2;
```

Вторая команда нарушает `CHECK (balance >= 0)`. PostgreSQL переводит транзакцию в состояние ошибки. Для завершения выполните:

```sql
ROLLBACK;
```

Если после такой ошибки отправить `COMMIT`, PostgreSQL завершит ошибочную транзакцию откатом, а не сохранит первое изменение.

**Примечание преподавателю:** демонстрируйте команды последовательно в одном подключении. Поведение SQL-клиента зависит от режима выполнения и autocommit.

## Часть IV. Принципы ACID (40–50 минут)

| Свойство | Значение | Пример |
|---|---|---|
| **A — Atomicity** | Атомарность | Списание и зачисление выполняются вместе |
| **C — Consistency** | Согласованность | Соблюдаются ограничения, например `CHECK` |
| **I — Isolation** | Изолированность | Конкурентные операции управляются уровнями изоляции и блокировками |
| **D — Durability** | Долговечность | Подтверждённые изменения сохраняются после сбоя согласно настройкам надёжности |

**Атомарность:** либо подтверждены все изменения, либо ни одно.

**Согласованность:** транзакция должна сохранять установленные ограничения. При этом корректную бизнес-логику должен обеспечить разработчик.

**Изолированность:** параллельные транзакции не должны некорректно влиять друг на друга. Уровень изоляции PostgreSQL по умолчанию — `READ COMMITTED`.

**Долговечность:** после успешного подтверждения PostgreSQL обеспечивает сохранность изменений в соответствии с настройками надёжности.

## Часть V. Точки сохранения (50–60 минут)

`SAVEPOINT` создаёт точку внутри транзакции. К ней можно вернуться, отменив только более поздние изменения.

| Команда | Назначение |
|---|---|
| `SAVEPOINT name` | Создать точку |
| `ROLLBACK TO SAVEPOINT name` | Отменить изменения после точки |
| `RELEASE SAVEPOINT name` | Удалить точку без отката |

### Пример 1. Одна точка

```sql
BEGIN;

UPDATE accounts
SET balance = balance + 1000
WHERE id = 1;

SAVEPOINT step1;

UPDATE accounts
SET balance = balance + 5000
WHERE id = 2;

ROLLBACK TO SAVEPOINT step1;

COMMIT;
```

Начисление Али сохранится, а начисление Мураду отменится.

### Пример 2. Две точки

```sql
BEGIN;

UPDATE accounts SET balance = balance + 100 WHERE id = 1;
SAVEPOINT first_step;

UPDATE accounts SET balance = balance + 200 WHERE id = 2;
SAVEPOINT second_step;

UPDATE accounts SET balance = balance + 300 WHERE id = 3;

ROLLBACK TO SAVEPOINT second_step;
COMMIT;
```

Сохранятся первые два изменения, третье отменится.

**Вопрос:** чем `ROLLBACK` отличается от `ROLLBACK TO SAVEPOINT`?

## Часть VI. Банковский перевод (60–70 минут)

**Задача:** перевести 2 000 ₽ со счёта Анны на счёт Давида.

Наивная реализация:

```sql
BEGIN;
UPDATE accounts SET balance = balance - 2000 WHERE id = 3 AND balance >= 2000;
UPDATE accounts SET balance = balance + 2000 WHERE id = 4;
COMMIT;
```

**Ошибка логики:** если у отправителя недостаточно денег, первый `UPDATE` изменит 0 строк, но второй всё равно начислит деньги. Транзакция сама по себе не проверяет бизнес-условия.

### Процедура с проверками

```sql
CREATE OR REPLACE PROCEDURE transfer_money(
    sender_id INTEGER,
    receiver_id INTEGER,
    amount NUMERIC
)
LANGUAGE plpgsql
AS $$
DECLARE
    affected_rows INTEGER;
BEGIN
    IF amount <= 0 THEN
        RAISE EXCEPTION 'Сумма перевода должна быть положительной';
    END IF;

    IF sender_id = receiver_id THEN
        RAISE EXCEPTION 'Нельзя переводить деньги самому себе';
    END IF;

    UPDATE accounts
    SET balance = balance - amount
    WHERE id = sender_id AND balance >= amount;

    GET DIAGNOSTICS affected_rows = ROW_COUNT;
    IF affected_rows <> 1 THEN
        RAISE EXCEPTION 'Счёт отправителя не найден или недостаточно средств';
    END IF;

    UPDATE accounts
    SET balance = balance + amount
    WHERE id = receiver_id;

    GET DIAGNOSTICS affected_rows = ROW_COUNT;
    IF affected_rows <> 1 THEN
        RAISE EXCEPTION 'Счёт получателя не найден';
    END IF;
END;
$$;
```

Вызов:

```sql
BEGIN;
CALL transfer_money(3, 4, 2000);
COMMIT;
```

Если процедура выдаст ошибку, завершите транзакцию командой `ROLLBACK;`. Процедура не содержит собственных команд `COMMIT` или `ROLLBACK`: управление транзакцией остаётся у вызывающего кода.

Для реального банковского приложения нужны дополнительные проверки, аудит и требования к надёжности.

## Часть VII. Самостоятельная работа (70–85 минут)

Перед заданиями при необходимости восстановите исходные данные:

```sql

INSERT INTO accounts (owner, balance)
VALUES
    ('Али', 10000),
    ('Мурад', 3000),
    ('Анна', 15000),
    ('Давид', 7000);
```

### Задание 1. Перевод денег (простое)

Переведите 1 500 ₽ от Али Мураду. Используйте `BEGIN`, два `UPDATE`, `COMMIT` и `SELECT`. Ожидаемый результат: Али — 8 500 ₽, Мурад — 4 500 ₽.

### Задание 2. Отмена операции (простое)

Начните транзакцию, добавьте Анне 5 000 ₽, выполните `ROLLBACK`. Убедитесь, что баланс не изменился.

### Задание 3. Ошибка внутри транзакции (среднее)

```sql
BEGIN;
UPDATE accounts SET balance = balance + 1000 WHERE id = 1;
UPDATE accounts SET balance = -1000 WHERE id = 2;
```

Ответьте: почему возникла ошибка, что произошло с транзакцией, как отменить изменения, сохранилось ли первое начисление? Выполните `ROLLBACK`.

### Задание 4. Точка сохранения (среднее)

В одной транзакции начислите Али 500 ₽, создайте `SAVEPOINT step1`, начислите Мураду 1 000 ₽, вернитесь к точке и выполните `COMMIT`. Проверьте результат.

### Задание 5. Несколько точек сохранения (среднее)

Начислите Али 1 000 ₽, Мураду 2 000 ₽, Анне 3 000 ₽. После первых двух операций создайте точки сохранения. Отмените только последнее начисление и сохраните остальные.

### Задание 6. Безопасный перевод (повышенное)

Используйте `transfer_money()`. Проверьте успешный перевод 2 000 ₽, перевод суммы больше остатка и отрицательную сумму. Объясните, какие проверки выполняются.

### Задание 7. Оформление заказа (повышенное)

Создайте таблицы:

```sql
CREATE TABLE inventory (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL,
    quantity INTEGER NOT NULL CHECK (quantity >= 0)
);

CREATE TABLE orders (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    product_id INTEGER REFERENCES inventory(id),
    quantity INTEGER NOT NULL CHECK (quantity > 0)
);

INSERT INTO inventory (name, quantity)
VALUES ('Ноутбук', 10), ('Мышь', 30), ('Клавиатура', 20);
```

Оформите заказ на три ноутбука: начните транзакцию, уменьшите остаток при наличии товара, добавьте заказ, подтвердите транзакцию. Проверьте обе таблицы.

**Дополнительный вопрос:** как проверить, что списание действительно изменило одну строку, прежде чем создавать заказ?

### Итоговые шаблоны

Подтверждение:

```sql
BEGIN;
-- SQL-операции
COMMIT;
```

Отмена:

```sql
BEGIN;
-- SQL-операции
ROLLBACK;
```

Частичная отмена:

```sql
BEGIN;
-- Первая операция
SAVEPOINT step1;
-- Вторая операция
ROLLBACK TO SAVEPOINT step1;
COMMIT;
```

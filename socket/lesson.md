# Часть I. Теория: как взаимодействуют сетевые приложения (0–15 мин)

## 2. Вводный вопрос

**Спросить студентов:**

> «Когда мы открываем сайт или отправляем сообщение в приложение, как программа на нашем компьютере узнаёт, кому нужно передать данные и как получить ответ?»

Выслушать 2–3 ответа, затем сформулировать:

- Приложение формирует запрос по определённым правилам.
- Операционная система помогает установить связь и передать байты.
- Сеть доставляет пакеты к другому узлу.
- Другая программа получает данные, обрабатывает их и возвращает ответ.

**Ключевая мысль:** приложение не управляет всеми этапами доставки самостоятельно. Эту работу разделяют сетевые уровни.

## 3. Модели OSI и TCP/IP

### Модель OSI (7 уровней)

| № | Уровень OSI | Основная задача | Пример |
|---|---|---|---|
| 7 | Прикладной | Сетевые функции для приложений | HTTP, DNS, SMTP |
| 6 | Представления | Форматирование, кодирование данных | Кодировки, форматы данных |
| 5 | Сеансовый | Управление сеансами взаимодействия | Логика сеанса |
| 4 | Транспортный | Передача данных между процессами | TCP, UDP |
| 3 | Сетевой | IP-адресация и передача между сетями | IPv4, IPv6 |
| 2 | Канальный | Передача кадров в пределах канала | Ethernet, Wi-Fi |
| 1 | Физический | Передача физических сигналов | Кабель, радиосигнал |

### Модель TCP/IP (4 уровня)

| Уровень TCP/IP | Что обеспечивает | Примеры |
|---|---|---|
| Прикладной | Правила взаимодействия программ | HTTP, DNS, SSH, наш учебный протокол |
| Транспортный | Общение между процессами | TCP, UDP |
| Интернет | Доставку IP-пакетов между узлами | IPv4, IPv6 |
| Сетевого доступа | Передачу данных через конкретную сеть | Ethernet, Wi-Fi |

**Пояснение:** модель OSI полезна для изучения и диагностики; TCP/IP описывает реально используемый стек. Деление функций на уровни — это учебная модель, а не требование, чтобы у каждого уровня была отдельная программа.

### Пример: отправляем текст «Привет»

```text
Приложение          создаёт сообщение: «Привет»
      ↓
TCP                  передаёт поток байтов между процессами по портам
      ↓
IP                   использует IP-адреса отправителя и получателя
      ↓
Ethernet / Wi-Fi     передаёт данные по локальной сети
      ↓
          КОМПЬЮТЕР ПОЛУЧАТЕЛЯ
      ↑
Приложение          читает данные и выводит: «Привет»
```

**Мини-вопросы для аудитории:**

1. Какой уровень отвечает за формат команды `GUESS 50`? — **Прикладной**.
2. Какой уровень предоставляет TCP-порты? — **Транспортный**.
3. На каком уровне используются IP-адреса? — **Интернет / сетевой**.

# Часть II. Прикладной уровень и реальные сервисы (15–30 мин)

## 4. Что такое прикладное сетевое взаимодействие

**Клиент** — программа, обращающаяся к другой программе за данными или услугой.  
**Сервер** — программа, принимающая обращения и предоставляющая услугу.  
**Сетевая служба** — функция, к которой можно обратиться через сеть.  
**Прикладной протокол** — правила, которые задают структуру и смысл запросов и ответов.

### Пример клиент-серверного взаимодействия

```text
Компьютер студента                         Компьютер преподавателя
┌──────────────────────┐                   ┌──────────────────────┐
│ Python client.py     │                   │ Python server.py     │
│                      │  «GUESS Alex 50»  │                      │
│ IP: 192.168.1.21     │ ────────────────> │ IP: 192.168.1.10     │
│ Временный TCP-порт   │ <──────────────── │ TCP-порт: 5000       │
│                      │     «МЕНЬШЕ»      │                      │
└──────────────────────┘                   └──────────────────────┘
```

*Адреса примерные — в аудитории используются реальные адреса устройств.*

### Что такое сокет

**Сокет (socket)** — программный интерфейс, с помощью которого приложение взаимодействует с сетевым стеком операционной системы. В Python используется встроенный модуль `socket`.

- **IP-адрес** помогает найти нужный сетевой интерфейс узла.
- **Порт** помогает передать данные нужному процессу/службе.
- **TCP** обеспечивает упорядоченный и надёжный поток байтов, но **не выделяет границы сообщений приложения**.
- Приложение само устанавливает формат команд: в нашей игре каждая команда заканчивается переводом строки `\n`.

### Часто используемые прикладные протоколы

| Протокол | Назначение | Распространённый порт |
|---|---|---|
| DNS | Поиск записей о доменных именах | UDP/TCP 53 |
| HTTP | Передача веб-ресурсов | TCP 80 |
| HTTPS | HTTP с защитой TLS | TCP 443; HTTP/3 также использует UDP 443 |
| SMTP | Передача электронной почты | TCP 25 между почтовыми серверами |
| IMAP | Доступ к почтовому ящику | TCP 143 / 993 (TLS) |
| SSH | Удалённое администрирование | TCP 22 |

**Отдельно подчеркнуть:** свой прикладной протокол можно придумать самим; он не обязан называться HTTP.

## 5. Быстрая демонстрация: DNS (5 мин)

**Действия преподавателя:**

1. Открыть PowerShell или командную строку Windows.
2. Выполнить:

```powershell
nslookup example.com
```

3. Показать в выводе имя, полученные IP-адреса и используемый DNS-сервер.
4. Выполнить:

```powershell
nslookup -type=MX gmail.com
```

**Объяснение:** записи DNS отвечают на разные вопросы. Например, A/AAAA указывают адреса, а MX — почтовые серверы для домена.

**Проверочный вопрос:** «Если на одном сервере изменится IP-адрес, почему удобно обращаться к нему по имени?»

## 6. Быстрая демонстрация: HTTP в браузере (5 мин)

1. Открыть Chrome или Edge.
2. Нажать **F12 → Network**.
3. Посетить `https://example.com`.
4. Выбрать запрос документа; открыть вкладки **Headers**, **Response**, **Timing**.
5. Показать метод `GET`, статус, заголовки и содержимое ответа.

**Пояснить различия:**

- `GET` — запрос ресурса.
- `200 OK` — запрос успешно обработан.
- `404 Not Found` — сервер доступен, но ресурс не найден.
- `500 Internal Server Error` — ошибка на стороне сервера.

**Вопрос аудитории:** «Значит ли ошибка 404, что TCP-соединение не удалось?» — **Нет: HTTP-ответ от сервера был получен.**

> **Если времени мало:** оставьте демонстрацию `nslookup` и один HTTP-запрос. Дополнительные эксперименты вынесены в конец конспекта.

# Часть III. Общий проект «Сетевой сейф» (30–65 мин)

## 7. Задача проекта

Преподаватель запускает **один общий TCP-сервер** на своём компьютере. Сервер загадывает число от 1 до 100. Каждый студент пишет и запускает Python-клиент, который отправляет числа и получает подсказки.

**Правила игры:**

1. Студент указывает имя и IP-адрес сервера.
2. Клиент отправляет `GUESS имя число`.
3. Сервер отвечает `БОЛЬШЕ`, `МЕНЬШЕ` или сообщает о победе.
4. Первый угадавший получает очко; сервер загадывает новое число.
5. Команда `TOP` показывает рейтинг игроков.
6. `EXIT` завершает клиентскую программу.

### Наш простой прикладной протокол

| Запрос клиента | Ответ сервера (пример) |
|---|---|
| `GUESS Anna 50` | `БОЛЬШЕ` |
| `GUESS Anna 75` | `МЕНЬШЕ` |
| `GUESS Anna 62` | `ПОБЕДА! Anna открыл(а) сейф!` |
| `TOP` | `Anna: 1; Ivan: 0` — если такие записи уже есть |
| `GUESS Anna abc` | `Ошибка: нужно ввести число` |

Каждый запрос и ответ — **одна строка в кодировке UTF-8, оканчивающаяся `\n`**. Это и есть правила нашего учебного прикладного протокола.

**Упрощения:** имена — без пробелов; сервер обрабатывает подключения последовательно, каждое подключение используется для одной команды. Баллы существуют, пока работает программа. Это учебная игра, а не защищённый многопользовательский сервис: идентификация по имени не является аутентификацией.

## 8. Подготовка сети (3 мин)

На компьютере преподавателя:

```powershell
ipconfig
```

Найти IPv4-адрес активного Ethernet- или Wi-Fi-интерфейса, например `192.168.1.10`.

Условия:

- Компьютеры должны иметь сетевую связность (обычно одна локальная сеть).
- На сервере должен быть установлен Python 3.
- При необходимости разрешить входящие TCP-подключения **только для частной/учебной сети** к порту `5000` в брандмауэре Windows; не отключать брандмауэр целиком.
- В гостевой Wi-Fi-сети может быть включена изоляция клиентов.
- Для проверки сначала можно запустить сервер и клиент на одном компьютере через `127.0.0.1`.

**Проверка из PowerShell на компьютере студента после запуска сервера:**

```powershell
Test-NetConnection 192.168.1.10 -Port 5000
```

Заменить IP на настоящий адрес компьютера преподавателя. Поле `TcpTestSucceeded: True` означает, что TCP-подключение к указанному порту удалось.

## 9. Код преподавателя: `server.py` (7–10 мин)

Объяснять код по частям: создание сокета → выбор IP/порта → ожидание клиента → чтение команды → выбор ответа → отправка ответа.

```python
import random
import socket

HOST = "0.0.0.0"
PORT = 5000

secret = random.randint(1, 100)
scores = {}

with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as server:
    server.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    server.bind((HOST, PORT))
    server.listen()

    print("Сетевой сейф запущен на порту", PORT)
    print("Секретное число:", secret)  # Только для преподавателя

    while True:
        connection, address = server.accept()

        with connection:
            connection.settimeout(10)
            try:
                reader = connection.makefile("r", encoding="utf-8")
                message = reader.readline().strip()
                reader.close()
            except (OSError, UnicodeError):
                print("Ошибка получения запроса от", address)
                continue

            print("От", address, "получено:", message)
            parts = message.split()

            if parts == ["TOP"]:
                if scores:
                    leaders = sorted(
                        scores.items(),
                        key=lambda item: item[1],
                        reverse=True
                    )
                    response = "; ".join(
                        f"{name}: {points}" for name, points in leaders
                    )
                else:
                    response = "Пока нет победителей"

            elif len(parts) == 3 and parts[0] == "GUESS":
                name = parts[1]

                try:
                    guess = int(parts[2])
                except ValueError:
                    response = "Ошибка: нужно ввести число"
                else:
                    if not 1 <= guess <= 100:
                        response = "Введите число от 1 до 100"
                    elif guess < secret:
                        response = "БОЛЬШЕ"
                    elif guess > secret:
                        response = "МЕНЬШЕ"
                    else:
                        scores[name] = scores.get(name, 0) + 1
                        response = f"ПОБЕДА! {name} открыл(а) сейф!"
                        secret = random.randint(1, 100)
                        print("Новый секрет:", secret)

            else:
                response = "Неизвестная команда"

            try:
                connection.sendall((response + "\n").encode("utf-8"))
            except OSError:
                print("Не удалось отправить ответ:", address)
```

**Как запустить:**

```powershell
python server.py
```

**Разбор ключевых строк:**

| Строка | Что означает |
|---|---|
| `socket.AF_INET` | IPv4 |
| `socket.SOCK_STREAM` | Потоковый сокет, обычно TCP |
| `bind((HOST, PORT))` | Привязать сервер к адресу и порту |
| `0.0.0.0` | Принимать соединения на доступных IPv4-интерфейсах |
| `listen()` | Перевести сокет в режим ожидания подключений |
| `accept()` | Принять клиента; вернуть соединение и адрес |
| `readline()` | Читать сообщение до символа `\n` |
| `sendall()` | Передать байты ответа |

> **Подсказка преподавателю:** не показывайте секретное число на проекторе во время игры. Строка `print("Секретное число:", secret)` нужна только для отладки — её можно убрать перед соревнованием.

## 10. Код студентов: `client.py` (10–12 мин)

**Студенты создают файл `client.py` и набирают следующий код:**

```python
import socket

server_ip = input("IP сервера: ")
name = input("Ваше имя: ").strip().replace(" ", "_")

while True:
    print("\nВведите число от 1 до 100")
    print("TOP — рейтинг, EXIT — выход")
    command = input("> ").strip()

    if command.upper() == "EXIT":
        break

    if command.upper() == "TOP":
        request = "TOP"
    else:
        request = f"GUESS {name} {command}"

    try:
        with socket.create_connection((server_ip, 5000), timeout=5) as client:
            client.sendall((request + "\n").encode("utf-8"))
            reader = client.makefile("r", encoding="utf-8")
            response = reader.readline().strip()
            reader.close()
            print("Ответ сервера:", response)
    except OSError:
        print("Ошибка: нет связи с сервером")
```

**Запуск:**

```powershell
python client.py
```

**Что объяснить во время набора кода:**

- `socket.create_connection()` устанавливает TCP-соединение с сервером.
- `sendall()` отправляет строку как последовательность байтов.
- `encode("utf-8")` преобразует строку в байты; `readline()` возвращает текст, поскольку поток открыт с `encoding="utf-8"`.
- `while True` позволяет выполнять несколько ходов, создавая **новое TCP-соединение для каждого хода**.
- `try/except` обрабатывает ситуацию, когда сервер недоступен.

**Важный опыт:** спросить, почему в клиенте указан именно IP преподавателя, а не `127.0.0.1`. Ответ: `127.0.0.1` всегда указывает на **тот же компьютер, на котором запущен клиент**.

# Часть IV. Наблюдаем сетевой трафик в Wireshark (65–80 мин)

## 12. Захват TCP-пакетов игры (10 мин)

**На компьютере преподавателя:**

1. Запустить Wireshark **до очередного хода**.
2. Выбрать интерфейс Ethernet или Wi-Fi, через который подключаются студенты.
3. Ввести отображающий фильтр:

```wireshark
tcp.port == 5000
```

4. Попросить одного студента выполнить один ход.
5. Найти SYN, SYN/ACK, ACK, сегменты с данными и закрытие соединения.

### Ожидаемая последовательность

```text
Студент                                 Преподаватель
  | -------- SYN --------------------------> |
  | <------- SYN, ACK ---------------------- |
  | -------- ACK --------------------------> |
  | -------- GUESS Anna 50\n --------------> |
  | <------- БОЛЬШЕ\n --------------------- |
  | -------- ACK --------------------------> |
  |          ... закрытие TCP ...           |
```

*Набор и порядок отдельных ACK/FIN в реальном захвате могут отличаться: TCP умеет объединять подтверждения, а стороны могут по-разному закрывать соединение.*

**Фильтр только для сегментов с данными:**

```wireshark
tcp.port == 5000 && tcp.len > 0
```

**Запросы к серверу:**

```wireshark
tcp.dstport == 5000
```

**Ответы сервера:**

```wireshark
tcp.srcport == 5000
```

**По адресу одного студента:**

```wireshark
ip.addr == 192.168.1.21 && tcp.port == 5000
```

*Замените пример IP адресом участника.*

## 13. Follow TCP Stream (3 мин)

Правой кнопкой мыши по пакету с данными → **Follow → TCP Stream**.

В окне диалога должны быть видны две стороны обмена, например:

```text
GUESS Anna 50
БОЛЬШЕ
```

**Объяснить:** это **полезная нагрузка TCP**, а не служебные поля IP или TCP. Мы смогли прочитать её, поскольку собственный прикладной протокол передаёт данные без шифрования.

Покажите в панели байтов, что слова в UTF-8 кодируются байтами. Дополнительно можно попросить студента отправить сообщение с латинскими буквами: `GUESS Anna 50`.

## 14. Сравнение HTTP и HTTPS (2 мин + при наличии времени)

**Вариант А: браузер.** В DevTools → Network открыть `https://example.com`, показать заголовки HTTP, доступные самому браузеру **после расшифровки**. Затем показать в Wireshark, что внешний пассивный наблюдатель не получает так же открыто содержимое HTTPS.

**Вариант Б: терминал Windows.**

```powershell
curl.exe --http1.1 -v https://example.com
```

Смотреть соединение и заголовки в `curl`; в Wireshark использовать фильтр `tcp.port == 443` (в этом примере HTTP/1.1 поверх TLS/TCP). Внешний захват показывает TLS, а не обычный незашифрованный HTTP-текст. Современные браузеры также могут использовать HTTP/3 через QUIC/UDP 443, поэтому лучше не делать вывод «весь HTTPS использует TCP».

**Основная идея:** TCP обеспечивает транспорт, но **не шифрует содержимое**. Для конфиденциальности обычно применяется TLS (как в HTTPS).

### Эксперимент на локальном HTTP без дополнительного приложения (необязательно)

Если нужно явно показать HTTP в открытом виде, на компьютере преподавателя выполнить в каталоге с тестовой HTML-страницей:

```powershell
python -m http.server 8000 --bind 0.0.0.0
```

Студент открывает `http://IP_ПРЕПОДАВАТЕЛЯ:8000`, преподаватель использует фильтр `tcp.port == 8000` и **Follow TCP Stream**. Этот небольшой HTTP-сервер предназначен только для учебной локальной сети, не для размещения сайта в интернете. Порт 8000 может также потребовать отдельного разрешения в брандмауэре.

## 15. Вопросы студентам (5 мин)

1. Для чего нужен прикладной уровень TCP/IP?
2. Что является клиентом и сервером в нашей игре?
3. Почему мы выбрали порт 5000?
4. В чём различие IP-адреса и порта?
5. Что делает `connect()` и когда отправляются байты сообщения?
6. Что такое `GUESS Anna 50`: TCP-команда или команда нашего протокола?
7. Для чего в протоколе нужен символ `\n`?
8. Почему Wireshark может прочитать наш запрос?
9. Что защищает HTTPS и за счёт чего?
10. Как отличить ошибку DNS от ошибки TCP-подключения и HTTP 404?

### Краткие ответы для преподавателя

1. Определяет правила обмена данными между сетевыми программами.
2. Клиент — программа студента; сервер — программа преподавателя.
3. Это выбранный нами порт прослушивания; можно было взять другой свободный порт.
4. IP — адрес сетевого интерфейса; порт — идентификатор точки взаимодействия транспортного протокола с процессом.
5. `connect()` устанавливает TCP-соединение, `sendall()` передаёт данные приложения.
6. Команда нашего собственного прикладного протокола.
7. Чтобы получатель понимал, где заканчивается одна команда.
8. Наш протокол передаёт текст без шифрования.
9. TLS шифрует и защищает данные HTTP при передаче (при корректной проверке подлинности сервера).
10. DNS — не удалось разрешить имя; TCP — не удалось соединиться; HTTP 404 — сервер ответил, но ресурс отсутствует.

## 16. Итог занятия (5 мин)

Вернуться к схеме:

```text
[Python-клиент]                    [Python-сервер]
      GUESS Anna 50  ─── TCP ────>  Анализ команды
      Получение       <── TCP ───  Ответ «БОЛЬШЕ»

Наш протокол  →  прикладной уровень
TCP           →  транспортный уровень
IP            →  уровень интернет
Ethernet/Wi-Fi→  уровень сетевого доступа
```

**Финальная мысль:** сегодня студенты не просто использовали готовое сетевое приложение, а создали собственную сетевую службу и своими глазами увидели, как её сообщения передаются по сети.

# Дополнительные материалы для преподавателя

## 17. Команды для быстрой демонстрации и самостоятельных экспериментов

| Задача | Команда Windows PowerShell / CMD | Что наблюдать |
|---|---|---|
| Узнать локальный IP | `ipconfig` | IPv4-адрес активного интерфейса |
| Проверить DNS | `nslookup example.com` | Адреса домена |
| Найти почтовые серверы | `nslookup -type=MX gmail.com` | MX-записи |
| Проверить порт игры | `Test-NetConnection 192.168.1.10 -Port 5000` | `TcpTestSucceeded` |
| Увидеть HTTP-заголовки | `curl.exe -I https://example.com` | Код ответа, заголовки |
| Подробный HTTPS-запрос | `curl.exe --http1.1 -v https://example.com` | TLS, запрос и ответ со стороны клиента |
| Посмотреть локальные TCP-сокеты | `netstat -ano -p tcp` | Локальные порты, состояния TCP, PID |

**Важно:** `curl.exe` указан явно, чтобы избежать неоднозначности с возможными оболочечными псевдонимами команды `curl` в Windows.

## 18. Возможные проблемы и решения

| Проблема | Возможная причина | Что проверить |
|---|---|---|
| `ConnectionRefusedError` | Сервер не запущен или порт не прослушивается | Запущен ли `server.py`, совпадает ли порт |
| Подключение долго не устанавливается | Межсетевой экран, изоляция Wi-Fi, неправильный IP | `ipconfig`, правила брандмауэра, `Test-NetConnection` |
| Клиент соединяется только на компьютере преподавателя | В клиенте указан `127.0.0.1` | Использовать настоящий IPv4-адрес преподавателя |
| `Address already in use` | Порт занят другим процессом или старой копией сервера | Проверить `netstat -ano -p tcp`, закрыть старый сервер |
| В Wireshark не видно пакетов | Выбран неверный интерфейс, захват включён поздно | Выбрать рабочий Ethernet/Wi-Fi и снова подключить клиента |
| На одном ПК не видно loopback | Захват ведётся на Wi-Fi/Ethernet вместо loopback | Использовать Npcap Loopback Adapter |
| DNS-запросов нет в захвате браузера | Кэш/DoH/другой интерфейс | Использовать `nslookup` и проверить интерфейс |
| В Wireshark нет понятного текста HTTPS | HTTP защищён TLS | Это ожидаемое поведение |
| В ответе ошибки или часть строки | Ввод не соответствует правилам учебного протокола | Проверить `GUESS имя число` и перевод строки |

## 19. Дополнительная самостоятельная работа, если группа успевает

Не обязательно выполнять на основном занятии. Достаточно предложить одну из задач:

1. **Счётчик попыток клиента.** После каждого ввода числа увеличивать локальный счётчик и показывать его на экране.
2. **Проверка ввода.** Не отправлять запрос, если введено не число от 1 до 100.
3. **Команда `HELP`.** Изменить сервер так, чтобы он возвращал список команд.
4. **Команда `PLAYERS`.** На сервере хранить множество имён игроков, которые уже отправляли запросы, и выводить их список.
5. **Обсуждение безопасности.** Почему любой участник может отправить команду с чужим именем? Что понадобилось бы для настоящей аутентификации?

## 20. Рекомендации по проведению

- **До начала занятия:** проверить локальную сеть и установить Wireshark/Npcap; узнать IP преподавателя; испытать работу клиента с другого компьютера.
- **Во время объяснения:** на проекторе показать сначала схему уровней, затем работающую игру и реальные пакеты.
- **Во время игры:** не раскрывать секретное число; заранее продумать короткий раунд, чтобы участие приняли несколько студентов.
- **Если компьютеры студентов не видят сервер:** используйте один тестовый клиент на компьютере преподавателя с адресом `127.0.0.1` и захватывайте трафик через loopback; сам принцип останется виден.
- **Не открывать порт 5000 в интернет:** служба предназначена для учебной сети и не имеет аутентификации и шифрования.
- **К чему перейти дальше:** HTTP как стандартизованный прикладной протокол, JSON, REST API, а затем многопользовательский чат и параллельная обработка подключений.

# Часть I. Теоретический материал

## 3. Что такое триггер?

**Триггер (Trigger)** — механизм PostgreSQL, который автоматически выполняет определённую функцию при наступлении заданного события в базе данных.

Например, в интернет-магазине пользователь изменяет цену товара:

```sql
UPDATE products
SET price = 70000
WHERE id = 1;
```

После выполнения команды PostgreSQL может автоматически:

- Записать старую и новую цену в журнал.
- Проверить допустимость изменения.
- Обновить связанные данные.
- Зафиксировать дату изменения.

Для этого используется триггер.

### Пример из реальной жизни

Представьте систему безопасности здания: датчик обнаруживает открытие двери, после чего система автоматически включает сигнализацию.

В PostgreSQL похожий принцип: **событие (`UPDATE`) → триггер → триггерная функция → запись изменения в журнал**.

**Главная особенность:** триггер не нужно вызывать вручную. Он срабатывает автоматически при заданном событии.

## 4. Чем триггер отличается от функции и процедуры?

| Функция | Процедура | Триггер |
|---|---|---|
| Вызывается через `SELECT` | Вызывается через `CALL` | Срабатывает автоматически |
| Может возвращать значение | Выполняет набор команд | Реагирует на событие |
| `CREATE FUNCTION` | `CREATE PROCEDURE` | `CREATE TRIGGER` |
| Используется для вычислений и других операций | Используется для выполнения операций | Используется для автоматизации действий |

Пример функции:

```sql
SELECT get_product_price(1);
```

Пример процедуры:

```sql
CALL update_product_price(1, 70000);
```

Пример срабатывания триггера:

```sql
UPDATE products
SET price = 70000
WHERE id = 1;
```

Если на таблице `products` установлен соответствующий триггер, PostgreSQL автоматически выполнит его функцию.

**Вопрос студентам:** почему нельзя просто использовать процедуру для записи истории изменения цены?

**Ответ:** процедуру необходимо специально вызывать. Триггер сработает при изменении цены обычным `UPDATE`, независимо от того, какая часть приложения выполнила запрос.

# Часть II. Структура триггера

## 5. Из каких частей состоит триггер?

В PostgreSQL для создания триггера обычно нужны два элемента:

1. **Триггерная функция** — определяет, какие действия необходимо выполнить.
2. **Триггер** — определяет, когда и при каком событии вызвать функцию.

### Шаг 1. Создание триггерной функции

```sql
CREATE FUNCTION trigger_function()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    RAISE NOTICE 'Триггер сработал!';
    RETURN NEW;
END;
$$;
```

`RETURNS TRIGGER` — специальный тип результата для триггерной функции.

`NEW` содержит новую строку, с которой выполняется операция. Для триггера `INSERT` или `UPDATE`, работающего на уровне строк, её можно вернуть через `RETURN NEW`.

### Шаг 2. Создание триггера

```sql
CREATE TRIGGER my_trigger
AFTER INSERT ON products
FOR EACH ROW
EXECUTE FUNCTION trigger_function();
```

| Элемент | Назначение |
|---|---|
| `CREATE TRIGGER` | Создаёт триггер |
| `my_trigger` | Название триггера |
| `AFTER INSERT` | Срабатывает после добавления |
| `ON products` | Таблица, к которой привязан |
| `FOR EACH ROW` | Выполняется для каждой строки |
| `EXECUTE FUNCTION` | Указывает триггерную функцию |

### Проверка

```sql
INSERT INTO products (name, price, quantity)
VALUES ('USB-кабель', 500, 20);
```

```text
NOTICE: Триггер сработал!
```

**Объяснение:** мы не вызывали `trigger_function()` вручную. Она выполнилась автоматически.

## 6. BEFORE и AFTER

### BEFORE — перед операцией

Используется, когда необходимо проверить или изменить данные до их сохранения.

Примеры: проверить цену товара, запретить отрицательное количество, автоматически исправить введённые значения.

### AFTER — после операции

Используется, когда необходимо выполнить дополнительные действия после изменения данных.

Примеры: сохранить историю изменения цены, записать факт удаления, добавить запись в журнал событий.

| BEFORE | AFTER |
|---|---|
| До операции | После операции |
| Можно изменить `NEW` | Изменение `NEW` не влияет на уже выполненную операцию |
| Можно отменить операцию для строки через `RETURN NULL` | Возвращаемое значение игнорируется |
| Подходит для проверки и изменения данных | Подходит для журналирования |

Оба вида триггеров выполняются в рамках той же операции с базой данных; `AFTER` не означает, что изменения уже окончательно зафиксированы.

## 7. NEW и OLD

- `NEW` — новые данные строки.
- `OLD` — предыдущие данные строки.

| Операция | NEW | OLD |
|---|---|---|
| `INSERT` | Новая строка | Недоступна |
| `UPDATE` | Изменённая строка | Строка до изменения |
| `DELETE` | Недоступна | Удаляемая строка |

Пример изменения цены: `OLD.price = 65000`, `NEW.price = 70000`.

```sql
OLD.price
NEW.price
NEW.name
NEW.quantity
```

Важно: `NEW` и `OLD` в таком виде используются в триггерах уровня строк (`FOR EACH ROW`).

# Часть III. Демонстрация преподавателя

## 8. Триггер BEFORE INSERT: проверка цены

**Задача:** запретить добавление товаров с отрицательной ценой.

### Шаг 1. Создадим триггерную функцию

```sql
CREATE FUNCTION check_product_price()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    IF NEW.price < 0 THEN
        RAISE EXCEPTION 'Цена не может быть отрицательной';
    END IF;

    RETURN NEW;
END;
$$;
```

`RAISE EXCEPTION` вызывает ошибку и прерывает выполнение операции, если ошибка не перехвачена. В отличие от неё, `RAISE NOTICE` лишь выводит сообщение.

### Шаг 2. Создадим триггер

```sql
CREATE TRIGGER check_price_trigger
BEFORE INSERT ON products
FOR EACH ROW
EXECUTE FUNCTION check_product_price();
```

### Шаг 3. Проверим

Корректные данные:

```sql
INSERT INTO products (name, price, quantity)
VALUES ('Колонка', 3000, 5);
```

Некорректные данные:

```sql
INSERT INTO products (name, price, quantity)
VALUES ('Колонка', -500, 5);
```

```text
ERROR: Цена не может быть отрицательной
```

**Вопрос:** почему проверку лучше выполнить до добавления строки?

## 9. Триггер BEFORE UPDATE: автоматическое исправление данных

**Задача:** если пользователь пытается установить отрицательное количество товара, автоматически заменить его на 0.

```sql
CREATE FUNCTION fix_product_quantity()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    IF NEW.quantity < 0 THEN
        NEW.quantity := 0;
    END IF;

    RETURN NEW;
END;
$$;
```

```sql
CREATE TRIGGER fix_quantity_trigger
BEFORE UPDATE ON products
FOR EACH ROW
EXECUTE FUNCTION fix_product_quantity();
```

Проверка:

```sql
UPDATE products
SET quantity = -10
WHERE id = 1;

SELECT id, name, quantity
FROM products
WHERE id = 1;
```

| id | name | quantity |
|---|---|---:|
| 1 | Ноутбук | 0 |

Хотя пользователь передал `-10`, триггер изменил значение на `0`.

**Обсуждение:** в каких ситуациях лучше автоматически исправлять значение, а в каких — выдавать ошибку?

# Часть IV. Триггеры для DELETE и TG_OP

## 10. Триггер AFTER DELETE

**Задача:** при удалении товара выводить сообщение с его названием.

```sql
CREATE FUNCTION notify_product_deleted()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    RAISE NOTICE 'Удалён товар: %', OLD.name;
    RETURN OLD;
END;
$$;
```

```sql
CREATE TRIGGER product_deleted_trigger
AFTER DELETE ON products
FOR EACH ROW
EXECUTE FUNCTION notify_product_deleted();
```

Проверка:

```sql
INSERT INTO products (name, price, quantity)
VALUES ('Тестовый товар', 100, 1);

DELETE FROM products
WHERE name = 'Тестовый товар';
```

```text
NOTICE: Удалён товар: Тестовый товар
```

При удалении доступна переменная `OLD`, поскольку новая версия удалённой строки отсутствует.

## 11. Что такое TG_OP?

`TG_OP` — специальная переменная триггерной функции, содержащая название операции, вызвавшей триггер.

Возможные значения: `INSERT`, `UPDATE`, `DELETE`, `TRUNCATE`. В этом занятии используем первые три.

### Пример универсальной триггерной функции

```sql
CREATE FUNCTION log_product_action()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    IF TG_OP = 'INSERT' THEN
        RAISE NOTICE 'Добавлен товар: %', NEW.name;

    ELSIF TG_OP = 'UPDATE' THEN
        RAISE NOTICE 'Изменён товар: %', NEW.name;

    ELSIF TG_OP = 'DELETE' THEN
        RAISE NOTICE 'Удалён товар: %', OLD.name;
    END IF;

    RETURN NULL;
END;
$$;
```

```sql
CREATE TRIGGER product_action_trigger
AFTER INSERT OR UPDATE OR DELETE
ON products
FOR EACH ROW
EXECUTE FUNCTION log_product_action();
```

`RETURN NULL` здесь допустим, поскольку для `AFTER`-триггеров возвращаемое значение игнорируется.

Теперь одна триггерная функция обрабатывает три разных события.

# Часть V. Практический пример: история изменения цен

## 12. Задача

В интернет-магазине необходимо сохранять историю изменения цен. При каждом изменении цены система должна автоматически записывать ID товара, старую цену, новую цену, дату и время изменения.

## 13. Создание таблицы истории

```sql
CREATE TABLE price_history (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    product_id INTEGER,
    old_price NUMERIC(10, 2),
    new_price NUMERIC(10, 2),
    changed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## 14. Создание триггерной функции

```sql
CREATE FUNCTION save_price_history()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    IF OLD.price IS DISTINCT FROM NEW.price THEN
        INSERT INTO price_history (
            product_id,
            old_price,
            new_price
        )
        VALUES (
            OLD.id,
            OLD.price,
            NEW.price
        );
    END IF;

    RETURN NEW;
END;
$$;
```

`OLD.price IS DISTINCT FROM NEW.price` проверяет, действительно ли значение изменилось, корректно учитывая также `NULL`.

## 15. Создание триггера

```sql
CREATE TRIGGER price_history_trigger
AFTER UPDATE OF price ON products
FOR EACH ROW
EXECUTE FUNCTION save_price_history();
```

## 16. Проверка работы

```sql
UPDATE products
SET price = 80000
WHERE id = 1;

SELECT * FROM price_history;
```

Пример результата, если предыдущая цена составляла 75000:

| id | product_id | old_price | new_price | changed_at |
|---|---|---:|---:|---|
| 1 | 1 | 75000 | 80000 | 2026-11-12 10:30:00 |

*Дата и время приведены для примера.*

**Главный вывод:** журнал пополняется автоматически, даже если пользователь выполняет обычный `UPDATE` без вызова специальной функции или процедуры.

# Часть VI. Управление триггерами

## 17. Просмотр триггеров

```sql
SELECT
    trigger_name,
    event_manipulation,
    event_object_table
FROM information_schema.triggers
WHERE event_object_table = 'products';
```

## 18. Удаление триггера

```sql
DROP TRIGGER check_price_trigger ON products;
```

Триггер удаляется, но связанная с ним функция остаётся.

```sql
DROP FUNCTION check_product_price();
```

## 19. Временное отключение триггера

```sql
ALTER TABLE products
DISABLE TRIGGER check_price_trigger;
```

Повторное включение:

```sql
ALTER TABLE products
ENABLE TRIGGER check_price_trigger;
```

Для выполнения этих команд необходимы соответствующие права. **Примечание:** команды отключения и включения выполняются только для существующего триггера. Если ранее выполнен `DROP TRIGGER`, его необходимо создать заново.

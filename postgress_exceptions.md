Представим интернет-магазин GameBox. Покупатель пытается оформить заказ, однако возникают проблемы:

- Товара недостаточно на складе.

# Часть II. Что такое ошибки и исключения? (10–20 минут)

## 1. Понятие ошибки

**Ошибка** — ситуация, при которой PostgreSQL не может корректно выполнить определённую операцию.

Например:

```sql
SELECT 10 / 0;
```

Результат:

```text
ERROR: division by zero
```

Другой пример:

```sql
INSERT INTO lesson_products (name, price, quantity)
VALUES ('Новая игра', -500, 10);
```

Если для цены установлено ограничение `CHECK (price > 0)`, PostgreSQL не позволит добавить запись.

## 2. Основные виды ошибок

| Вид ошибки | Пример |
|---|---|
| Деление на ноль | `10 / 0` |
| Нарушение уникальности | Добавление повторяющегося уникального значения |
| Нарушение `CHECK` | Отрицательная цена |
| Нарушение внешнего ключа | Продажа несуществующего товара |
| Ошибка пользовательской проверки | Недостаточное количество товара |
| Ошибка преобразования данных | Преобразование текста `'abc'` в число |

В PL/pgSQL можно обнаруживать такие ситуации и **перехватывать ошибки, чтобы выполнить предусмотренное действие**.

## 3. Подготовка учебной базы данных

Для практических примеров создадим отдельные таблицы GameBox, чтобы не изменять данные предыдущей контрольной работы.

### Таблица товаров

```sql
CREATE TABLE lesson_products (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name VARCHAR(100) UNIQUE NOT NULL,
    price NUMERIC(10, 2) NOT NULL CHECK (price > 0),
    quantity INTEGER NOT NULL CHECK (quantity >= 0)
);

INSERT INTO lesson_products (name, price, quantity)
VALUES
    ('Шахматы', 1200, 8),
    ('Монополия', 2500, 5),
    ('Уно', 500, 15),
    ('Дженга', 900, 10),
    ('Мафия', 700, 12);
```

### Таблица продаж

```sql
CREATE TABLE lesson_sales (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    product_id INTEGER REFERENCES lesson_products(id),
    quantity INTEGER NOT NULL CHECK (quantity > 0),
    total NUMERIC(10, 2) NOT NULL CHECK (total > 0),
    sold_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

Проверьте данные:

```sql
SELECT * FROM lesson_products;
```

| ID | Название | Цена | Количество |
|---|---|---:|---:|
| 1 | Шахматы | 1200 | 8 |
| 2 | Монополия | 2500 | 5 |
| 3 | Уно | 500 | 15 |
| 4 | Дженга | 900 | 10 |
| 5 | Мафия | 700 | 12 |

# Часть III. Оператор RAISE (20–35 минут)

`RAISE` позволяет выводить сообщения и самостоятельно создавать ошибки в PL/pgSQL.

У него есть несколько уровней сообщений. На начальном этапе рассмотрим три основных.

| Оператор | Назначение | Прерывает выполнение? |
|---|---|---|
| `RAISE NOTICE` | Информационное сообщение | Нет |
| `RAISE WARNING` | Предупреждение | Нет |
| `RAISE EXCEPTION` | Ошибка | Да, если не перехвачена |

## 1. RAISE NOTICE — информационное сообщение

Используется, когда нужно сообщить о выполнении какого-либо действия.

```sql
DO $$
BEGIN
    RAISE NOTICE 'Добро пожаловать в GameBox!';
END;
$$;
```

Результат:

```text
NOTICE: Добро пожаловать в GameBox!
```

Оператор не останавливает выполнение блока.

### Передача значений в сообщение

Символ `%` используется как место для подстановки значения.

```sql
DO $$
DECLARE
    product_name TEXT := 'Монополия';
    product_price NUMERIC := 2500;
BEGIN
    RAISE NOTICE 'Товар: %, цена: %',
        product_name, product_price;
END;
$$;
```

Результат:

```text
NOTICE: Товар: Монополия, цена: 2500
```

## 2. RAISE WARNING — предупреждение

Предупреждение используется, когда нужно обратить внимание на потенциальную проблему, но не останавливать работу.

```sql
DO $$
DECLARE
    stock INTEGER := 3;
BEGIN
    IF stock < 5 THEN
        RAISE WARNING 'Товар скоро закончится!';
    END IF;

    RAISE NOTICE 'Проверка завершена';
END;
$$;
```

Результат:

```text
WARNING: Товар скоро закончится!
NOTICE: Проверка завершена
```

**Объяснение:** предупреждение не остановило выполнение, поэтому второе сообщение тоже появилось.

## 3. RAISE EXCEPTION — создание ошибки

`RAISE EXCEPTION` используется, когда продолжать выполнение нельзя.

```sql
DO $$
DECLARE
    amount INTEGER := -3;
BEGIN
    IF amount <= 0 THEN
        RAISE EXCEPTION
            'Количество товара должно быть положительным';
    END IF;

    RAISE NOTICE 'Операция выполнена';
END;
$$;
```

Результат:

```text
ERROR: Количество товара должно быть положительным
```

Сообщение «Операция выполнена» не появится.

**Важно:** `RAISE EXCEPTION` вызывает ошибку. Если она не обработана, выполнение блока прекращается.

### Дополнительная возможность: HINT

Можно дополнить ошибку подсказкой:

```sql
RAISE EXCEPTION 'Некорректная цена'
    USING HINT = 'Укажите цену больше нуля';
```

Это полезно, когда необходимо объяснить пользователю, как исправить проблему. Эта команда используется внутри блока PL/pgSQL.

# Часть IV. Обработка исключений: EXCEPTION WHEN (35–50 минут)

До этого момента мы самостоятельно создавали ошибки. Теперь научимся **перехватывать уже возникшие ошибки**.

## 1. Синтаксис EXCEPTION WHEN

Общая структура блока PL/pgSQL:

```sql
BEGIN
    -- Основные действия

EXCEPTION
    WHEN название_ошибки THEN
        -- Действия при ошибке
END;
```

Когда внутри блока возникает подходящее исключение, PostgreSQL прекращает выполнение обычных команд этого блока и переходит в соответствующий обработчик `WHEN`.

## 2. Пример: обработка деления на ноль

Создадим функцию, которая делит одно число на другое.

```sql
CREATE OR REPLACE FUNCTION safe_divide(
    a NUMERIC,
    b NUMERIC
)
RETURNS NUMERIC
LANGUAGE plpgsql
AS $$
DECLARE
    result NUMERIC;
BEGIN
    result := a / b;

    RETURN result;

EXCEPTION
    WHEN division_by_zero THEN
        RAISE NOTICE 'Ошибка: деление на ноль!';
        RETURN 0;
END;
$$;
```

Проверка:

```sql
SELECT safe_divide(10, 2);
SELECT safe_divide(10, 0);
```

| Вызов | Результат |
|---|---:|
| `safe_divide(10, 2)` | 5 |
| `safe_divide(10, 0)` | 0 |

Во втором случае также появится уведомление.

Здесь `0` используется как учебное значение при ошибке. В реальных вычислениях часто лучше возвращать `NULL` или явно сообщать об ошибке, чтобы не выдавать ноль за правильный результат деления.

## 3. Основные виды исключений

PostgreSQL поддерживает именованные условия ошибок, которые можно указывать после `WHEN`.

| Исключение | Когда возникает |
|---|---|
| `division_by_zero` | Деление на ноль |
| `unique_violation` | Нарушение уникальности |
| `check_violation` | Нарушение ограничения `CHECK` |
| `foreign_key_violation` | Нарушение внешнего ключа |
| `not_null_violation` | Попытка записать `NULL` в обязательное поле |
| `OTHERS` | Большинство остальных ошибок |

`OTHERS` не перехватывает абсолютно все условия, поэтому его лучше применять осознанно.

## 4. Пример: обработка повторяющегося товара

В таблице `lesson_products` название товара должно быть уникальным. Попробуем добавить шахматы второй раз.

```sql
DO $$
BEGIN
    INSERT INTO lesson_products (name, price, quantity)
    VALUES ('Шахматы', 1500, 5);

EXCEPTION
    WHEN unique_violation THEN
        RAISE NOTICE 'Такой товар уже существует!';
END;
$$;
```

Результат:

```text
NOTICE: Такой товар уже существует!
```

Запись с повторяющимся названием не добавится.

**Небольшое задание:** измените название товара на новое и проверьте, сработает ли обработчик ошибки.

## 5. Пример: обработка нескольких ошибок

Можно обрабатывать разные исключения в одном блоке.

```sql
DO $$
BEGIN
    INSERT INTO lesson_products (name, price, quantity)
    VALUES ('Новая игра', -500, 10);

EXCEPTION
    WHEN unique_violation THEN
        RAISE NOTICE 'Такой товар уже существует';

    WHEN check_violation THEN
        RAISE NOTICE 'Нарушено ограничение таблицы';
END;
$$;
```

В этом случае появится сообщение о нарушении ограничения `CHECK`.

## 6. SQLERRM и SQLSTATE

Внутри обработчика исключения доступны две специальные переменные:

- `SQLERRM` — текст возникшей ошибки.
- `SQLSTATE` — пятисимвольный код возникшей ошибки.

```sql
DO $$
BEGIN
    PERFORM 10 / 0;

EXCEPTION
    WHEN OTHERS THEN
        RAISE NOTICE 'Сообщение: %', SQLERRM;
        RAISE NOTICE 'Код ошибки: %', SQLSTATE;
END;
$$;
```

Результат:

```text
NOTICE: Сообщение: division by zero
NOTICE: Код ошибки: 22012
```

Это полезно для диагностики ошибок и создания понятных сообщений пользователям.

# Часть V. Практический пример: процедура оформления покупки (50–65 минут)

Теперь объединим ранее изученные темы:

- Процедуры.
- Условные операторы `IF`.
- SQL-запросы `SELECT`, `UPDATE`, `INSERT`.
- Обработку ошибок.
- Транзакции.

## Задача

Покупатель хочет приобрести игру. При оформлении покупки система должна:

1. Проверить количество покупаемых экземпляров.
2. Найти товар.
3. Проверить остаток на складе.
4. Уменьшить количество товара.
5. Добавить запись о продаже.
6. Сообщить об ошибке, если оформить покупку невозможно.

## Создание процедуры

```sql
CREATE OR REPLACE PROCEDURE buy_game(
    p_product_id INTEGER,
    p_amount INTEGER
)
LANGUAGE plpgsql
AS $$
DECLARE
    v_price NUMERIC;
    v_quantity INTEGER;
BEGIN
    -- Проверяем количество
    IF p_amount <= 0 THEN
        RAISE EXCEPTION 'Количество должно быть больше нуля';
    END IF;

    -- Получаем данные товара
    SELECT price, quantity
    INTO v_price, v_quantity
    FROM lesson_products
    WHERE id = p_product_id;

    -- Проверяем существование товара
    IF NOT FOUND THEN
        RAISE EXCEPTION 'Товар не найден';
    END IF;

    -- Проверяем остаток
    IF v_quantity < p_amount THEN
        RAISE EXCEPTION 'Недостаточно товара на складе';
    END IF;

    -- Уменьшаем остаток
    UPDATE lesson_products
    SET quantity = quantity - p_amount
    WHERE id = p_product_id;

    -- Создаём продажу
    INSERT INTO lesson_sales (
        product_id,
        quantity,
        total
    )
    VALUES (
        p_product_id,
        p_amount,
        v_price * p_amount
    );

    RAISE NOTICE 'Покупка успешно оформлена!';

EXCEPTION
    WHEN OTHERS THEN
        RAISE NOTICE 'Ошибка оформления: %', SQLERRM;
        RAISE;
END;
$$;
```

### Разбор процедуры

| Элемент | Назначение |
|---|---|
| `p_product_id` | ID покупаемого товара |
| `p_amount` | Количество |
| `v_price` | Цена товара |
| `v_quantity` | Остаток товара |
| `IF` | Проверка условий |
| `RAISE EXCEPTION` | Сообщение об ошибке |
| `EXCEPTION WHEN OTHERS` | Обработка возникшей ошибки |
| `SQLERRM` | Получение текста ошибки |
| `RAISE;` | Повторное возбуждение той же ошибки |

В конце процедуры используем `RAISE;` без параметров, чтобы не скрывать ошибку от вызывающего кода. Это позволяет внешней транзакции корректно завершиться откатом.

## Проверка № 1. Успешная покупка

```sql
BEGIN;

CALL buy_game(2, 2);

COMMIT;
```

Ожидаемый результат:

```text
NOTICE: Покупка успешно оформлена!
```

Проверьте:

```sql
SELECT * FROM lesson_products;
SELECT * FROM lesson_sales;
```

Количество «Монополии» уменьшится с 5 до 3 экземпляров. В таблице продаж появится запись на сумму 5 000 рублей.

## Проверка № 2. Недостаточно товара

```sql
BEGIN;

CALL buy_game(3, 100);
```

Результат будет содержать:

```text
NOTICE: Ошибка оформления: Недостаточно товара на складе
ERROR: Недостаточно товара на складе
```

После ошибки отмените транзакцию:

```sql
ROLLBACK;
```

Количество товара не изменится, продажа не сохранится.

## Проверка № 3. Несуществующий товар

```sql
CALL buy_game(999, 2);
```

Ожидаемая ошибка:

```text
ERROR: Товар не найден
```

## Проверка № 4. Отрицательное количество

```sql
CALL buy_game(1, -3);
```

Ожидаемая ошибка:

```text
ERROR: Количество должно быть больше нуля
```

**Примечание преподавателю:** пример рассчитан на последовательное учебное выполнение. Для реального магазина дополнительно потребовалась бы защита от конкурентных покупок одного и того же товара.

# Часть VI. Исключения и транзакции (65–70 минут)

Студенты уже проходили `BEGIN`, `COMMIT` и `ROLLBACK`. Теперь важно объяснить, как обработка исключений связана с отменой изменений.

## Что происходит, если возникает ошибка?

В PostgreSQL блок PL/pgSQL с обработчиком `EXCEPTION` обладает особым свойством: если внутри него возникла обработанная ошибка, изменения данных, выполненные внутри этого блока до ошибки, откатываются.

При этом изменения, сделанные до входа в этот блок, не обязательно отменяются.

### Пример

Сначала посмотрите количество шахмат:

```sql
SELECT quantity
FROM lesson_products
WHERE id = 1;
```

Теперь выполните:

```sql
DO $$
BEGIN
    -- Увеличиваем количество шахмат
    UPDATE lesson_products
    SET quantity = quantity + 10
    WHERE id = 1;

    -- Пытаемся добавить дубликат товара
    INSERT INTO lesson_products (name, price, quantity)
    VALUES ('Шахматы', 2000, 5);

EXCEPTION
    WHEN unique_violation THEN
        RAISE NOTICE 'Ошибка! Изменения внутри блока отменены';
END;
$$;
```

Вторая операция нарушает ограничение `UNIQUE`.

Первая операция тоже будет отменена, поскольку находится внутри того же блока с обработчиком исключений.

Проверьте:

```sql
SELECT quantity
FROM lesson_products
WHERE id = 1;
```

Количество шахмат останется таким же, как до выполнения блока.

**Важно:** `BEGIN ... END` внутри PL/pgSQL обозначает программный блок и **не является** командой начала SQL-транзакции `BEGIN;`.

# Часть VII. Самостоятельная практическая работа (70–85 минут)

Для закрепления студенты выполняют задания на базе GameBox.

## Задание 1. Проверка стоимости товара

**Тема:** `RAISE EXCEPTION`.

Создайте функцию `check_price()`, которая принимает цену товара и возвращает её, если она положительная.

Требования:

- Если цена больше нуля, вернуть её.
- Если цена меньше или равна нулю, вызвать `RAISE EXCEPTION` с сообщением «Некорректная цена».

Проверьте:

```sql
SELECT check_price(1500);
SELECT check_price(-300);
```

## Задание 2. Предупреждение о малом остатке

**Тема:** `RAISE WARNING`.

Создайте процедуру `check_quantity()`, которая принимает ID товара и получает его количество из `lesson_products`.

Требования:

- Если количество меньше 5, вывести `RAISE WARNING 'Товар скоро закончится'`.
- Иначе вывести `RAISE NOTICE 'Товара достаточно'`.

Проверьте процедуру на нескольких товарах.

## Задание 3. Безопасное деление

**Тема:** `EXCEPTION WHEN`.

Создайте функцию `divide_numbers()`, которая принимает два числа и возвращает результат деления.

Если возникает `division_by_zero`, функция должна:

- Вывести сообщение «Деление на ноль запрещено».
- Вернуть `NULL`.

Проверьте:

```sql
SELECT divide_numbers(20, 4);
SELECT divide_numbers(15, 0);
```

## Задание 4. Обработка повторяющегося товара

**Тема:** `unique_violation`.

Создайте процедуру `add_product()`, которая принимает:

- Название товара.
- Цену.
- Количество.

Процедура должна добавлять товар в таблицу `lesson_products`.

# Методические рекомендации

Для этого занятия лучше использовать **практическую демонстрацию ошибок**, а не только объяснение синтаксиса.

При демонстрации сначала выполните неправильный запрос без обработки исключения, покажите сообщение PostgreSQL, а затем повторите пример с `EXCEPTION WHEN`. Так студенты увидят, зачем вообще нужен обработчик.

Особое внимание уделите различиям между `RAISE EXCEPTION` и `EXCEPTION WHEN`: первый оператор создаёт ошибку, второй позволяет её обработать.

Не стоит пока углубляться в `GET STACKED DIAGNOSTICS`, пользовательские коды ошибок, сложное логирование или конкурентные транзакции. Для 90-минутного занятия достаточно `RAISE`, `EXCEPTION WHEN`, распространённых видов ошибок, `SQLERRM` и `SQLSTATE`.
